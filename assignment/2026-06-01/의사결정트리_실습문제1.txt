# 문제 1. 현재 모델 성능 분석 ===============================
현재 생성된 모델의 다음 성능지표를 출력하시오.

* Accuracy
* Precision
* Recall
* F1-score
* Confusion Matrix


### 코드
```
from sklearn.metrics import accuracy_score
from sklearn.metrics import precision_score
from sklearn.metrics import recall_score
from sklearn.metrics import f1_score
from sklearn.metrics import confusion_matrix

acc = accuracy_score(y_test, predictions)

prec = precision_score(
    y_test,
    predictions,
    average='weighted'
)

rec = recall_score(
    y_test,
    predictions,
    average='weighted'
)

f1 = f1_score(
    y_test,
    predictions,
    average='weighted'
)

print("Accuracy :", acc)
print("Precision :", prec)
print("Recall :", rec)
print("F1 :", f1)

print(confusion_matrix(y_test,predictions))
```

- 결과 : 
```

Precision : 0.7237047722081982
Recall : 0.725
F1 : 0.7243338616585424
[[113  27]
 [ 28  32]]
```
### 질문에 대한 답을 작성하시오 : ---------------------------------------

1. Accuracy의 의미는?
- 전체 예측 데이터 중 모델이 실제 값(정답)을 맞춘 비율

2. Precision과 Recall 차이는?
- Precision : 모델이 Positive라고 예측한 것 중, 실제 Positive인 비율
- Recall : 실제 Positive인 전체 데이터 중, 모델이 Positive라고 올바르게 찾아낸 비율

3. 은행 대출 심사에서는 Recall이 중요한 이유는?
- 기본 전제: 대출 심사 모델에서 Positive(양성)의 정의는 "부도/미상환자"임
- Recall이 낮을 때의 문제점 (실제 부도자를 정상으로 오인):
> - 돈을 갚지 못할 사람에게 대출을 승인해 주게 됨
> - 대출 원금을 고스란히 떼이게 되므로 은행에 직접적이고 막대한 금융 손실 발생
- Precision이 낮을 때의 문제점 (정상인을 부도자로 오인):
> - 돈을 잘 갚을 사람에게 대출을 거절하게 됨
> - 잠재 고객 한 명을 잃어 '이자 수익'을 못 얻는 기회비용 손실에 그침

- 결론:
> - 고객 한 명을 놓치는 손실(Precision 저하)보다, 원금을 통째로 떼이는 손실(Recall 저하)이 비교할 수 없을 정도로 치명적임
> - 따라서 은행은 부도 예측 모델의 Recall(재현율)을 높여 리스크를 최소화하는 방향을 선택함

### 질문

## 질문 ------------------------------------------------
Entropy와 Gini 차이는?
- Gini (지니): 
> - 데이터셋에서 임의로 고른 아이템이 잘못 분류될 확률을 측정하며, 값이 0일 때 완전히 순수함을 뜻함
> - 계산식이 단순하여 학습 속도가 빠름

Entropy (엔트로피): 
> - 정보 이론에서의 '무질서도'나 '불확실성'을 측정하며, 모든 클래스가 균등하게 섞여 있을 때 최댓값(1)을 가짐
> - 로그 계산으로 인해 연산 속도가 상대적으로 느림

# 문제 8. 데이터 전처리 개선 ==========================================
One-Hot Encoding 적용 전후 성능을 비교하시오.

### 기존
```
LabelEncoder
```
### 변경
```
pd.get_dummies()
```
또는
```python
OneHotEncoder()
```
### 결과표

| Encoding             | Accuracy |
| ---------------------- | -------- 
| LabelEncoder     | 0.7300 |
| OneHotEncoder | 0.7100 | 

### 질문 -------------------------------------------------
One-Hot Encoding이 유리한 이유는?
- 독립적인 차원 분리: 범주 간의 연관성이 없는 문자열 데이터를 고유한 0과 1의 개별 열로 완전히 분리함
- 순서 및 가중치 왜곡 방지: `LabelEncoder`처럼 순서가 없는 범주에 임의의 숫자(0, 1, 2 ...)를 부여함으로써 트리 모델이 데이터 간의 서열이나 크기 관계(예: 0 < 1 < 2)로 오해하는 현상을 차단함
- 직관적인 이진 분기 수행: 특정 범주의 포함 여부(예: `해당 범주 == 1`)만을 기준으로 삼아 데이터를 좌우로 명확하게 쪼갤 수 있어 의사결정 나무의 분기 논리에 완벽히 부합함
> - 이론적 장점에도 불구하고 현재 결과표에서는 `LabelEncoder(0.7300)`가 `OneHotEncoder(0.7100)`보다 성능이 우수하게 나옴
> - 이는 범주형 변수의 가짓수가 너무 많아 원-핫 인코딩 후 데이터의 차원이 과도하게 늘어났거나, 특정 범주가 우연히 트리 분기에 유리한 가짜 서열을 형성했기 때문으로 분석됨
