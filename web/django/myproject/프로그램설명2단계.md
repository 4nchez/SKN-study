## 4. 게시글 관련 View 작성
boards/views.py

### 4-1. 게시글 목록 View
def board_list(request):
- 한 페이지에 출력할 목록 갯수 지정
- db 테이블에서 목록을 select 조회함 => ORM 사용함
- 반환받은 결과 리스트를 템플릿(html 파일)과 함께 사용자 브라우저로 보냄(render() 사용)

### 4-2. 새 게시글 등록 View
- 로그인한 회원만 게시글 등록 처리
- 작성한 BoardForm 사용함
- 반드시 Post로 전송 & 유효성 검사 true 상태여야 함
- DB에 저장 처리(insert into 쿼리문 자동 실행)
- 핵심: board.author = request.user

### 4-3. 게시글 상세 조회 View(내용 상세 보기)
- 요청에 사용자가 클릭한 글번호도 함께 전송와야 됨
- DB에서 Select 조회해 옴(게시글 한 개: 글번호(자동 생성된 id 사용:pk로 지정되어 있음) 이용)
- 조회수 1증가 처리
- 상세보기 템플릿과 함께 조회글 내보냄

### 4-4. 게시글 수정 View
- 로그인해야 함
- 작성자 본인만 수정 할 수 있게 함
- 몇번 게시글 수정인지 (update 구문 where절에 사용하기 위함) 글번호도 전송 받음
- 수정할 게시글 조회해 옴 > 수정할 내용 값 변경 적용 > DB에 수정 저장 처리

### 4-5. 게시글 삭제 View
- 본인 또는 관리자만 삭제(로그인 필수)
- 삭제할 글 번호(pk)도 요청시 같이 전송
- delete 쿼리문 작동: delete() 사용

## 13. 업로드 파일 url 처리
config(myproject)/urls.py에 추가함

```text
# settings 값을 읽음
from django.conf import settings

# 개발 서버에서 media 파일을 제공하기 위함
from django.conf.urls.static import static

# 맨 아래에 추가
# 개발 환경에서 사용자가 업로드한 파일을
# Django 개발 서버가 제공하도록 설정함
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

## 14. 최종 Migration
- settings.py 최종 점검 : 언어, 시간대, 타임존, 세션 타임아웃, DEBUG, DATABASE. dotenv, ROOT 경로 설정 등
- 모든 Model 작성이 끝났다면 다시 실행함
```bash
python manage.py makemigrations

python manage.py migrate
```
상태 확인:
```bash
python manage.py showmigrations
```
